# 시스템 관제 자동화 - 요구사항 수행 내역서

리눅스 서버에 네트워크 보안·권한 체계를 구축하고, 시스템 자원과 프로세스
상태를 관제하는 `monitor.sh`를 작성해 crontab으로 자동 실행한 전 과정을
정리한다. 실습 환경은 Ubuntu 22.04 LTS이며 일반 계정으로 작업했다.

## 1. 보안 및 권한 체계

### SSH 포트 변경 · Root 접속 차단
`/etc/ssh/sshd_config`에서 `Port 20022`, `PermitRootLogin no`로 설정하고
`systemctl restart sshd`로 반영했다. SSH 기본 포트(22)는 자동화 스캔·무차별
대입 공격의 1차 표적이므로, 포트를 20022로 옮기면 표적형 스캔 노출이 크게
줄어든다. Root 원격 접속 차단은 계정 탈취 시 즉시 최고 권한이 넘어가는 위험을
막아, 공격자가 반드시 일반 계정을 거치도록 강제한다(위협 모델상 공격 표면 축소).

### 방화벽
UFW를 활성화하고 `ufw allow 20022/tcp`, `ufw allow 15034/tcp`만 허용했다.
기본 정책은 deny incoming이므로 그 외 포트는 모두 차단된다.

### 계정 · 그룹
`agent-admin`, `agent-dev`, `agent-test` 계정과 `agent-common`, `agent-core`
그룹을 생성했다. `api_keys` 디렉토리와 로그 디렉토리는 `agent-core` 그룹으로
제한했다. 민감 자원 접근을 필요한 주체로만 좁히는 **최소 권한 원칙** 적용이다.

## 2. 애플리케이션 구동

환경 변수와 키 파일을 구성한 뒤 제공된 Python 앱을 실행해 Boot Sequence
5단계 `[OK]`를 모두 통과하고 `Agent READY` 출력과 15034 포트 LISTEN을
확인했다.

## 3. monitor.sh 설계

- **프로세스 식별**: `pgrep -f agent-app`를 사용했다. `ps | grep`은 grep
  자기 자신이 잡히는 문제가 있어 `pgrep`이 정확하다.
- **포트 확인**: `ss -ltn 'sport = :15034'`로 LISTEN 여부를 본다. `netstat`은
  미설치 환경이 많아 기본 제공되는 `ss`를 택했다.
- **자원 수집**: CPU/MEM은 `top -bn1`·`free`에서, DISK는 `df -P`에서 파싱했다.
  로그 포맷은 `타임스탬프 | CPU | MEM | DISK | 상태`로 고정해 후처리(파싱·집계)를
  쉽게 했다.
- **비정상 처리**: 프로세스 미존재 또는 포트 미개방이면 `exit 1`로 종료해
  cron/상위 감시가 실패를 감지하게 했다. 반면 방화벽 비활성·임계치 초과는
  **경고만 로그에 남기고 종료하지 않는다** — 관제는 계속 돌아야 하며, 이들은
  즉시 장애가 아니라 운영자가 판단할 상황이기 때문이다.
- **로그 누적**: `>>`로 append 한다. `>`는 매 실행마다 파일을 덮어써 이력이
  사라지므로, 누적 기록에는 반드시 `>>`가 필요하다.

## 4. 로그 자동화 · 용량 관리

`/var/log/agent-app/monitor.log`에 기록하며 소유자 `agent-dev`, 실행자는
`agent-admin`과 cron이다. logrotate로 10MB·10개 보관(size 10M, rotate 10)을
설정해 디스크 고갈을 예방한다.

```
* * * * * /home/agent-admin/monitor.sh
```

crontab에 매분 실행을 등록했고, `watch -n5 tail monitor.log`로 로그가 매분
증가함을 확인했다.

## 5. 운영 시나리오 대응

- **대상이 Nginx로 바뀌면**: 프로세스명(`nginx`), 포트(80/443), 로그 경로,
  임계값을 바꾸면 된다. 골격은 재사용 가능하다.
- **프로세스는 살아있는데 포트가 안 열릴 때**: 바인딩 실패(포트 충돌), 방화벽
  차단, 앱 초기화 미완 순으로 `ss`, `ufw status`, 앱 로그를 확인한다.
- **로그 급증으로 디스크가 찰 위험**: 단기로는 logrotate 강제 실행·오래된 로그
  압축, 중기로는 원격 로그 수집(중앙화)과 보존 정책 재조정으로 대응한다.
